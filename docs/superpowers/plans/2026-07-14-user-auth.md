# User Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add complete email/password account lifecycle and a minimal display-name profile without anonymous authentication.

**Architecture:** Supabase Auth owns credentials, email verification, recovery, and sessions. A RLS-protected `public.users` table owns application profile state; focused PostgreSQL RPCs own profile invariants, while thin authenticated Edge Functions orchestrate privileged Auth operations and normalize errors.

**Tech Stack:** PostgreSQL 17, Supabase Auth/CLI 2.95+, Supabase Edge Runtime, Deno 2.7, TypeScript, `@supabase/supabase-js`, Deno test.

---

- `supabase/sql_src/triggers/user/trg_handle_new_auth_user.sql`: Auth user bootstrap trigger.
- `supabase/functions/_shared/auth.ts`: JWT verification and authenticated-user extraction.
- `supabase/functions/_shared/edge.ts`: method, JSON, response, and stable error normalization.
- `supabase/functions/_shared/supabase.ts`: request-scoped and server-only Supabase clients.
- `supabase/functions/_shared/rate_limit.ts`: trusted request-IP normalization and database rate-limit adapter.

- `supabase/functions/v1/user/delete-account/*`: reauthenticated deletion orchestration, handler, and tests.
- `supabase/functions/_shared/security/tests/user_auth_sql_contract.test.ts`: static SQL/config security guardrails.

  migration matching SQL sources; its timestamp must come from the CLI rather than this plan.
- `package.json`: focused and aggregate auth verification commands.

```sql
create table public.users (
  user_id uuid primary key references auth.users (id) on delete cascade,
  display_name text not null,
  account_status text not null default 'active',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint users_display_name_length_check
    check (char_length(display_name) between 2 and 80),
  constraint users_display_name_trimmed_check check (display_name = btrim(display_name)),
  constraint users_account_status_check check (account_status = 'active')

alter table public.users enable row level security;
revoke all on table public.users from anon, authenticated;
grant select on table public.users to authenticated, service_role;
grant insert, update, delete on table public.users to service_role;
create policy users_self_read on public.users for select to authenticated
using (user_id = (select auth.uid()));
```

## Implementation Notes

- Supabase `scope: 'others'` revokes other refresh tokens but cannot invalidate already-issued
  access JWTs immediately. The explicit one-hour JWT expiry bounds this platform limitation.
- Client signup, sign-in, sign-out, resend confirmation, and recovery-email initiation remain native
  Supabase Auth SDK operations. The backend does not add redundant wrappers.
- The first implementation deliberately excludes OAuth, MFA, avatar, roles, public user IDs,
  settings, and soft deletion.
- Before claiming completion, compare hosted Auth settings with `supabase/config.toml`; remote
  deployment or Dashboard mutation remains outside this local implementation unless separately
  authorized.
